# Quantum iOS V3–V5 完整前端升级实施方案

版本：2026-09-17
状态：已在隔离沙箱实施，待用户验收
开发边界：独立沙箱；用户验收前不替换现有前端

## 1. 项目目标

在不改变现有后端接口、DTO、数据结构、认证协议、存储格式和工作流状态机的前提下，将现有 iOS SwiftUI 前端按 V3–V5 原型重新排版和视觉升级，形成一套完整、可运行、可验收的前端，而不是另建一套演示应用。

“1:1 复刻”指复刻原型手机屏幕内部的页面结构、视觉比例、组件层级、交互状态和动效节奏。设计板外部的手机金属边框、海报背景、编号与说明文字不进入 App。

## 2. 强制边界

### 2.1 必须保持不变

- GitHub 后端与产品仓库：`https://github.com/Johnie198946/ai-lab-platform`
- 后端目录：`backend/`
- iOS 目录：`ios/`
- `APIClient` 公共方法、endpoint、请求和响应字段
- DTO、`CodingKeys`、数据库模型与状态枚举
- JWT、Keychain、短信/OAuth 登录和协议确认流程
- SSE 事件、会话恢复、answer blocks 和长回答分页
- 工作流 clarification、plan、execution、artifact 状态机
- 笔记 Markdown/frontmatter、同步哈希和账号隔离
- 现有 ViewModel、Store 与路由职责

### 2.2 允许改变

- `AppTheme` 的语义颜色、字号、圆角、阴影、间距和动效令牌
- 现有 View 的布局、层级、组件外观、过渡和错误反馈
- 底部导航的视觉表现与显示文案，但仍绑定现有四个页面入口
- 不改变公开输入输出的渲染性能优化
- 原型中同一功能的状态展示方式

### 2.3 明确不做

- 不创建第二套 iOS App、第二套路由器或第二套数据模型
- 不把原型图直接铺成不可交互的页面
- 不伪造后端没有提供的数据或成功状态
- 不新增第三方 UI、Markdown、动画或图片缓存依赖
- 不在用户验收前提交、推送、部署或替换原前端

## 3. 原型合并规则

### 3.1 覆盖优先级

1. **V5 最优先**：启动页、旅行计划转旅行笔记、拍照＋随手写自动排版。
2. **V4 次优先**：登录错误、轻量思考、长按语音、澄清与合并、工作流、智能体、旅行计划、选词问答、节点评估、智能研究。
3. **V3 作为完整基线**：V4/V5 未覆盖的页面、状态、异常恢复和管理功能。

同一页面出现冲突时只保留最高版本，不拼贴不同版本的视觉结构。

### 3.2 品牌规则

- 唯一口号：**知识，让世界更大**。
- 使用官方 Quantum Logo，不重绘、不换色、不拉伸。
- 启动页 Logo 区不再出现旧口号或重复副标题。
- Quantum 青—蓝—紫渐变只用于 Logo、主焦点、选中态和核心生成动作。

## 4. 最终信息架构

底层仍使用现有四个根页面，仅按原型重新表达：

| 原型导航 | 现有页面职责 | 绑定内容 |
|---|---|---|
| 首页 | Chat | 新对话、历史会话、消息流、输入、导入、语音、澄清与知识操作 |
| 阅读 | Knowledge | 知识首页、笔记、搜索、书架、图书详情与阅读器 |
| 工作流 | Workflow | 普通任务、旅行计划、智能研究、执行、成果、画布与评估 |
| 我的 | Settings | 个人资料、智能体、记忆、用量、订阅、权益与治理 |

现有深链、返回逻辑、状态容器和页面生命周期保持不变。

## 6. 统一视觉规范

### 6.1 色彩令牌

| 语义 | 目标值/方向 |
|---|---|
| 页面背景 | `#FBFAF6` 暖象牙纸色 |
| 主文字 | `#182136` 深墨蓝 |
| 次文字 | `#647087` 中性灰蓝 |
| 发丝边框 | 深墨蓝约 10–13% 透明度 |
| 雾蓝 | `#EAF4FF` |
| 薄荷 | `#E4F6ED` |
| 淡紫 | `#F0ECFF` |
| 主蓝 | `#2A8EF0` |
| 主紫 | `#7058F6` |
| 错误 | 浅玫瑰背景＋清晰红色文字/图标，不只使用红边 |

所有颜色进入 `AppTheme`，页面不散落硬编码色值。

### 6.2 字体

- 系统操作、正文和控件：SF Pro / PingFang SC，全部支持 Dynamic Type。
- 知识标题、文章标题、旅行篇章：系统 serif / New York 风格。
- 正文行高约 1.5–1.7；手机长文每行约 35–60 个字符。
- 不引入字体包，不让字体加载阻塞首屏。

### 6.3 间距与形状

- 间距阶梯：4、8、12、16、24、32、40pt。
- 手机左右安全内容边距：16–20pt。
- 常规卡片圆角：16–20pt；Sheet：20–24pt；胶囊：完整圆角。
- 所有交互热区至少 44×44pt。
- 优先使用留白、浅底和发丝线，不靠厚重阴影堆层级。

### 6.4 图片与图标

- Logo 使用官方资源。
- 系统功能图标统一使用 SF Symbols，同一层级不混用 filled/outline。
- 旅行和阅读图片按原型比例裁切，预留稳定尺寸，避免加载后跳动。
- 有意义图片提供 VoiceOver 描述；纯装饰图片从辅助功能树隐藏。

## 7. 页面关键交互

### 7.1 启动与登录

- 首屏按 V5 保留 Logo、知识主视觉、圆形知识图片和两个登录层级。
- 手机号输入、验证码、协议和错误恢复按 V4 展开。
- 字段失焦或提交时展示字段级错误；VoiceOver 同步播报。
- 原型中的 Apple 按钮只复刻视觉层级；没有后端能力时不得伪造登录成功，实际入口使用现有可用认证方式。

### 7.2 Chat

- 空状态是轻量知识起点，不使用大型工具面板。
- 思考过程默认一行；仅在生成中显示轻量状态，完成后静止。
- 长按麦克风直接转写进输入框，不增加独立语音页面。
- 用户气泡使用小面积品牌色；助手长回答使用纸面正文。

### 7.3 阅读、提问和批注

- 选中文字后出现原生轻菜单：提问、批注、转存。
- 提问结果以引用原文＋简洁答案呈现。
- 保存为批注后在正文边缘和批注中心可回看。
- 转存笔记复用现有笔记模型，保留来源、书名、章节和引用文本。

### 7.4 工作流与智能体

- 创建页只显示目标、输出类型和参考资料；高级设置后置。
- 计划页按纵向步骤展示智能体、时长和主动作。
- 智能体能力通过 Sheet 预览，不跳入复杂管理页。
- 画布只负责可视编排，所有保存和运行继续使用现有 DSL/API。

### 7.5 旅行计划与旅行笔记

- Chat 中的一句话请求升级为现有工作流任务。
- 成果页组合地图、每日安排、摄影提示、住宿、美食、交通和风险。
- 保存到笔记时不复制任务卡片，而是转换为封面、每日篇章和实用附录。
- 拍照＋随手写允许保留原话、对照原文、只重排文字、只换版式和撤销。

## 8. 动效方案

| 场景 | 时长 | 实现原则 |
|---|---:|---|
| 按压反馈 | 120–180ms | opacity/scale，不能推动周围布局 |
| 小组件展开 | 180–240ms | 淡入＋6–10pt 位移 |
| 卡片/Sheet 进入 | 240–320ms | SwiftUI 原生 spring |
| 页面连续过渡 | 280–380ms | 每屏最多 1–2 个焦点 |
| 退出 | 进入时长的 60–70% | 更快且可中断 |

- 只动画 opacity、scale、offset。
- 不动画长文本高度、大图片尺寸和大面积 blur。
- `repeatForever` 仅用于真实加载、录音和运行状态。
- `accessibilityReduceMotion` 开启后改为直接切换或短淡入。

## 9. 性能方案

### 9.1 长回答

- 保留现有消息分页、字符上限、流式预览、SSE 节流和 answer blocks。
- 保留 `ChatMessageStreamView` 的已验证布局策略，不机械改为 `LazyVStack`。
- 长文不做整体 transition、matched geometry 或逐段入场。

### 9.2 超长笔记

- Markdown 解析、索引和大块文本预处理放到后台任务。
- 编辑态保持增量保存和防抖，不在每次输入时全量重排全部内容。
- 阅读态按块生成稳定 ID；目录和反链延迟加载。

### 9.3 图片

- 导入前用 ImageIO 按目标像素生成缩略图，避免先完整解码 48MP 原图。
- 卡片和列表按实际显示尺寸解码；限制内存缓存容量。
- 原图只在全屏预览或导出时按需读取。
- 长图显示尺寸设上限，避免创建超大 SwiftUI 布局表面。

### 9.4 动效与列表

- 长列表只给前 5 个首屏元素做入场效果。
- 禁止常驻 blur、3D 倾斜和装饰性无限动画。
- Instruments 验收关注主线程卡顿、峰值内存、图片解码与滚动掉帧。

## 10. 实施阶段

### 阶段 0：原型量化

- 将 V3–V5 每个手机画面拆分为独立页面/状态。
- 记录 393×852pt 目标画布上的组件边界、间距、颜色、字号和圆角。
- 输出页面到现有 SwiftUI View 的一一映射表。

### 阶段 1：设计系统与壳层

- 统一 `AppTheme`。
- 还原启动页、登录、底部导航、导航栏、按钮、输入框、卡片、Sheet。
- 验收：启动与登录页面截图对照。

### 阶段 2：Chat 与知识

- 完成 Chat、会话、输入、语音、思考、澄清、富内容和错误状态。
- 完成知识首页、笔记编辑/阅读、合并预览和长内容性能。
- 验收：V3/V4 对应状态逐屏截图。

### 阶段 3：工作流、旅行和智能研究

- 完成创建、计划、智能体参与、执行、人工门、成果预览。
- 完成旅行任务、旅行笔记、拍照记录与智能研究/PPT。
- 验收：V4/V5 对应状态逐屏截图。

### 阶段 4：智能体、阅读与设置

- 完成智能体创建、知识/工具 CRUD、画布、节点和评估。
- 完成书架、阅读、问答批注、设置、记忆、订阅和治理。
- 验收：所有剩余 V3/V4 状态逐屏截图。

### 阶段 5：系统验收

- 小屏、大屏、iPad、横竖屏布局。
- 最大 Dynamic Type、VoiceOver、Reduce Motion、浅色外观。
- 超长富文本、48MP 图片、长图、图片密集笔记压力测试。
- 构建、单元测试、UI 冒烟测试和截图差异检查。

## 11. 1:1 验收标准

### 11.1 视觉

- 以 iPhone 15 Pro 393×852pt 为基准截图。
- 页面主要组件边界相对原型误差不超过 2pt。
- 字号、字重、行距、圆角与间距使用统一令牌，关键值与原型一致。
- 对照方式：原型图、实现截图、50% 透明叠图三联验收。
- 官方 Logo 比例和颜色必须保持原始资源，不以肉眼重绘。

### 11.2 功能

- 每个原型状态必须由真实页面状态产生，不使用静态截图冒充。
- 所有现有 API 调用、错误恢复、分页、同步和工作流动作保持可用。
- 原型中后端不存在的能力不得伪造成功；以现有能力或明确不可用状态承载。

### 11.3 可用性与无障碍

- 触控区域至少 44×44pt。
- 正文对比度至少 4.5:1；大型文字和图形至少 3:1。
- 表单拥有可见标签、字段级错误与 VoiceOver 描述。
- 最大系统字号下内容可滚动且无不可达按钮。
- Reduce Motion 下无持续装饰动画。
- 固定导航和底部 CTA 不遮挡滚动内容或系统安全区。

### 11.4 性能

- 长回答流式输出保持可交互，不阻塞输入栏。
- 超长笔记打开时提供明确加载状态，不出现长时间白屏。
- 大图导入不先完整解码原图，列表滚动不重复同步解码。
- 性能退化必须有可复现用例和对应回归测试。

## 12. 交付与替换流程

1. 全部开发仅在独立沙箱完成。
2. 每个阶段提供原型/实现对照截图，不提前替换现有前端。
3. 完成全量构建、测试、性能与无障碍检查。
4. 用户确认整体视觉与交互。
5. 确认后才将最小差异迁移到正式仓库。
6. 迁移后再次构建和测试；未获得授权不 commit、不 push、不部署。

## 13. 完成定义

以下条件全部满足才可称为“前端升级完成”：

- V3 的 13 个功能域全部被现有真实页面覆盖。
- V4 的 13 组交互细化全部落入对应现有流程。
- V5 的 3 组最终覆盖完整实现。
- 没有新增平行架构、重复模型或替代接口。
- 视觉截图通过 1:1 对照验收。
- 长文本和大图性能通过专项测试。
- 用户明确确认后才进入原前端替换阶段。
