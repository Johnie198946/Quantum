# Quantum iOS 组件素材体检与旁路接入清单

## 结论

V3–V5 共 113 个页面/状态，但生产素材不应按页面重复制作。原型中的图片需求可收敛为 6 个可复用资产族；操作图标、状态图标和真实路线不应做成截图位图。

## 现有实现与缺口

| 资产族 | 原型用途 | 当前实现 | 缺口 |
|---|---|---|---|
| 书籍封面 | 书架、搜索、书籍详情、阅读入口 | `KnowledgeBookDTO` 已提供 `coverTheme/coverVariant/coverVersion`；`KnowledgeBookCover` 仅按列表索引切换两种渐变 | 未消费现有封面字段，没有正式封面素材 |
| 笔记/日记封面 | 最近笔记、日记、旅行笔记 | 日记仅由 `daily` 标签识别，卡片统一使用渐变和 SF Symbol | 没有按内容和稳定 ID 选择的封面素材 |
| 用户头像 | 我的、知识菜单、资料编辑 | `avatar_url` 当前保存 SF Symbol 名称；编辑页六选一 | 没有真实头像素材与兼容解析 |
| 内容型图标 | 学习、阅读、灵感、生活、研究、旅行等入口 | 同层级混用 filled/outline SF Symbols | 缺少统一的内容插画图标；系统操作图标应继续用 SF Symbols |
| 旅行图片 | 行程 Hero、每日景点、旅行笔记拼贴 | 现有切片只有 139–287px，放大后模糊 | 缺少适合 3x 屏幕的 Hero 和景点图 |
| 地图路线 | 旅行成果、旅行笔记 | `TravelRouteMap` 是硬编码贝塞尔曲线和地点 | 不是真实地图；现有工作流内容没有结构化坐标 |

|---|---:|---|---|---|

## 图标边界

- 返回、关闭、搜索、分享、加载、错误、播放、暂停等系统操作继续使用 SF Symbols。
- 学习、阅读、灵感、生活、研究、旅行等内容入口可以使用生成式插画图标。
- 所有交互区域仍由 SwiftUI `Button` 提供，图像本身不承担状态或点击语义。
- 位图图标必须提供 VoiceOver 标签；装饰图从辅助功能树隐藏。

## 旁路接入

- 保留 `APIClient`、DTO、Store、SSE 和现有 endpoint，不创建第二套网络层。
- DEBUG 启动参数只注入与正式 DTO 相同形状的预览数据；正式请求代码仍走原入口。
- 书封、日记封面、头像和内容图标由本地资产选择器解析；选择失败立即使用当前原生回退。
- 旅行产物继续从现有 artifact content endpoint 下载；利用已有 `metadata.renderType` 增加向后兼容的 `travel_plan_v1` JSON 解码。地图是 MapKit 真地图，当前连线表示地点顺序；需要逐路段导航时再调用 `MKDirections`。
- 用户确认前不删除预览开关、不替换正式入口、不提交、不推送、不部署。

`travel_plan_v1` 使用现有 `WorkflowArtifactContentDTO.content` 承载 JSON：

```json
{
  "destination": "日本 · 京都",
  "date_range": "4月12日 – 4月16日（5天）",
  "budget": "约 ¥8,000/人",
  "companions": 2,
  "style": "人文 · 美食",
  "stops": [
    { "name": "京都站", "latitude": 34.9858, "longitude": 135.7588 },
    { "name": "清水寺", "latitude": 34.9949, "longitude": 135.7850 }
  ]
}
```

未知字段由 Swift `Decodable` 忽略，缺失展示字段使用旁路预览默认值；`stops` 缺失时回退到京都预览坐标。

## 隐私与生成约束

- 生图只使用公开的通用主题和虚构人物，不发送用户日记、头像、客户名、私有知识或工作流正文。
- 图片内不烘焙标题、日期、作者、进度和路线状态；动态内容继续由 SwiftUI 绘制。
- 所有生成素材需检查文字伪影、人物一致性、边缘、裁切安全区和 3x 屏幕清晰度后再进入资产目录。
