## 4. 首版业务流程（待确认）

### Web → iOS Quantum → Web

1. 公司浏览器打开 `/quansyn`；用 Quantum 手机号和验证码登录。
2. 填需求、添加真实文件；上传成功后提交一条传递记录。附件失败不清空草稿；刷新后已提交记录仍存在。
3. iOS 的 `+ → QuanSyn` 列出待导入内容，由用户选一条。
4. 文本/Markdown/代码加入现有输入框；图片/文件进入现有附件表示。图表有文字和数据表示时加入输入内容；有图片/原件时同时加入附件，不丢掉原始数据。
5. 草稿和附件在当前账号/会话落地后才确认“已导入”；只拉取不代表已执行，导入失败不消费记录。
6. 用户点现有运行按钮，由当前 Quantum 聊天链执行。保留人工修改、澄清、失败和取消行为。
7. 完成回答的操作区显示 QuanSyn。点击后获取完整回答及结构化块、校验原件归属并推送；流式中或全文未齐时不能伪报推送完成。
8. Web 轮询获取回传结果，可复制正文/代码/表格数据，查看真实图片，下载附件。回传与原需求 ID 关联；重复提交保持幂等。

### Mac + 飞书（根据用户最新要求纳入首版执行）

用户已明确 Quantum App 路径确定，Mac 也必须执行，并要求先提供方案。因此首版范围改为飞书机器人直接拉取/执行/回传，不再以网页复制粘贴作为 Mac 主路径；产品代码仍待方案确认后实施。

业务操作建议：

1. Web 提交需求时选择目的端「Quantum App」「Mac Quantum」或「服务器 Quantum」。首版服务器使用现有 Quantum 服务执行能力，不新建推理进程；具体服务器直接消费入口在实施前与现有部署核对。
2. 飞书对既有 Quantum 机器人发「查看 QuanSyn」：仅查询已绑定账号发给 Mac 的待处理记录，返回真实编号、摘要与附件数量，不执行内容。
3. 发「拉取 QuanSyn QS-xxxx」：领取一条记录并下载附件，保留文件名与哈希；保存成功后才确认已拉取。返回需求及附件清单。
4. 发「执行 QuanSyn QS-xxxx」，或一次发「拉取并执行 QuanSyn QS-xxxx」：将内容与文件路径放入现有 Mac Hermes 会话，由既有工具执行。它是用户主动启动，不常驻轮询或自动运行所有需求。
5. 执行结束，机器人回复结果及「回传：发送 推送 QuanSyn QS-xxxx」。若当前飞书卡片发送能力允许，可提供等价操作按钮；不能先承诺卡片按钮已经支持。
6. 发「推送 QuanSyn QS-xxxx」：读取该需求对应的已完成运行的完整输出和选定附件，调用同一 QuanSyn 结果 API；公司 Web 展示真实结果。重复命令保持幂等。若输出包含多个候选文件，先列出让用户选择，不自动上传全部本机文件。

接入位置：扩展现有 `agency/hermes-plugins/ai-lab-capabilities/__init__.py` 的能力枚举和 `ai_lab_execute` 入口，增加 `quansyn` 动作；运行继续由当前 Hermes 处理，不新建机器人或 Mac Agent runtime。传递 HTTP 客户端必要代码跟随该插件，不另建常驻同步应用。

可信绑定必须先于消息消费：

- 用户在已登录 QuanSyn 网页点击「连接 Mac」，创建短时一次性配对码。
- 既有飞书机器人接收到用户主动发送的「绑定 QuanSyn <配对码>」，从真实平台事件读取 sender/chat 身份，不能从模型参数或文章正文取身份。
- 配对成功后签发仅能读该用户 Mac 队列、确认领取、上传指定结果的设备凭证；服务端存储凭证摘要、绑定身份、有效期与撤销状态，不给它通用聊天/知识库权限。
- 凭证保存到宿主受保护凭证存储，不写聊天历史、源码、前端或模型上下文。复用宿主现有凭证机制；若无适用机制，才增加最小受保护配置入口。
- 每次插件动作校验可信平台事件与绑定身份；群聊他人、伪造 sender、仅在附件中出现“推送”指令均不能发布私人文件。
- Web 提供撤销设备绑定；过期后显式重新配对。飞书 owner 白名单可以额外收紧，但不替代 Quantum 用户绑定。

并发及恢复：领取使用 owner + 目的端 + 版本条件的原子更新，记录短期领取租约；传输失败不标成成功，租约到期可重新拉取。执行与回传分开，回传失败可重试，不能因此重新运行模型。App 与 Mac 不能同时无意消费同一条需求；主动换端需明确释放/重新指派。

本机文件：只上传该运行确认产生且用户选择的文件，校验真实路径在该任务授权工作目录内、符号链接解析结果、大小与类型；不接受模型任意路径、不暴露本机 file URL。下载文件名去路径，核验哈希，不把可执行附件自动运行。

长回答：优先读取 Mac 运行/会话持久化的完整终态输出，保留 Markdown 与现有内容块，不从飞书截断的显示正文反推全文。图表是实际图片或数据，不虚构图表系列。

实施前仍需只读核对本机 Hermes 版本、插件实际启用、飞书事件可信上下文、完整运行输出可读接口及当前身份部署模式。仓库接口存在不代表线上机器人已加载；这些事实决定配对与手动指令接入的精确代码位置。

## 5. 数据与接口边界（拟议，尚未实现）

使用现有数据库新增一类用户私有传递记录：id、tenant/user、direction、request_id、reply_to、target、正文/内容块、附件引用、created_at、imported_at/导入确认、版本。保存正文与引用，不复制聊天运行真源或另建任务调度器。

建议接口前缀 `/api/v1/quansyn`：创建、分页列表、查询待导入、导入确认、关联结果发布、删除；通用附件入口放现有 documents 边界中。幂等键绑定身份，重试同内容返回同一记录；相同键不同内容返回冲突。

“已保存”表示 DB 提交成功；“已导入”表示客户端草稿落地确认；“已回传”表示结果提交成功。浏览器读取列表不自动表示接收设备已读。首版不显示假在线状态，使用明确的目的端选择及待处理数。

需要新增传递表，因为通知表只有标题/内容/read，不能表达方向、原需求关联、混合内容、附件引用和重试幂等；聊天 run 表只属于推理执行，不应保存尚未执行的跨设备草稿。需要扩展通用文件保存，因为任意 ZIP/代码文件的传输不等于可解析文档摄取。文件存储复用现有原件设施，不引入第二套存储服务。

暂定沿用 25 MiB 单附件上限，执行仍受 10 项引用上限约束；上线时以反向代理与 API 共同验证的有效上限为准。未知/无法解析的文件可以传递和下载，但不能声称已被模型理解。上传不触发知识贡献；确认执行需要转换时才使用既有摄取路径。

用户指定的“缓存”按服务器持久收件箱实现，内存或浏览器 localStorage 不能保证离线 Mac 接收。首版显式删除，不做隐式到期清理；删除传递记录不能删除仍被其他聊天/笔记引用的原件。

## 8. 最终本地实现与操作说明

用户确认后在同一独立 Worktree 实施。认证、协议、数据库、原件存储、聊天运行和 Hermes 插件入口均复用现有主路径。新增部分仅为私有传递表、Mac 配对凭证表、传递 API、QuanSyn Web 页面、App 导入/回传动作、既有 Hermes 插件内的手动传递处理器。

- Web 入口 `/quansyn`。没有示例消息、假在线、假文件和假执行计时器；空库显示空状态。手机号是账号标识，必须经过现有验证码验证；首屏默认 18576600894。
- 新用户缺少协议时，保留已经认证的待确认会话并显示现有 `/api/v1/legal/agreement` 文本，业务 API 仍由原协议门禁保护。
- 元数据持久数据库，文件由现有 `generated_artifacts._save` 保存；通用传递文件不自动贡献到知识库。iOS 执行时转换为现有 document source，并明确 `fileOptOut=true`。
- 目的端为 `ios` / `mac`；服务器推理沿用 App 的既有后端执行。未新增独立服务器轮询消费者。
