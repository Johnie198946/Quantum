## 为什么不合格

### 1. 选题越界

正文把用户自己的产品开发思路当成公开教程案例，并在结尾再次映射到 Quantum 产品方法。即使不泄露源码，也违反“用户自己的产品开发内容不得作为公开选题”的明确边界。

### 2. 不是给新手的操作攻略

文章把篇幅放在沙箱、CLI 参数作用域、验证器、执行日志、证据强度和产品方法论上。读者要先理解 Git、命令行、JSONL、Node、沙箱、静态验收等概念，才能进入任务；这与“非技术中文入门读者”不匹配。

虽然正文提供了一条命令和长提示词，但缺少真正的界面级节奏：每一步点哪里、输入什么、完成后应看到什么、看不到时怎么办。大量篇幅解释实验边界，实际任务结果反而被淹没。

### 3. 封面缺失是链路缺口，不只是漏图

`assets=[]` 证明稿件没有提交图片资产；同时目录 API 没有真实封面 URL 字段，阅读 API 也没有 hero cover 字段。仅在正文顶部插图只能解决阅读页的一部分，不能让书架卡片展示文章专属封面。

## 修订方向

- 新选题改为独立、通用、非产品开发任务：**《用 Gemini Notebook 把一份长 PDF 变成可核对的学习笔记》**。
- 目标读者：第一次使用 AI 阅读工具、不会写代码的人。
- 单一结果：读者完成一份带来源核对记录的学习笔记，而不是“了解 AI 工作流”。
- 文章结构：准备材料 → 上传 → 第一次提问 → 分块做笔记 → 点开引用核对 → 修正 → 导出 → 验收 → 故障恢复。
- 每一步固定包含：**操作、可复制输入、预期结果、失败恢复**。
- 删除 Quantum、用户产品、编码智能体、Git、Node、验证器、内部 Skill、发行证据链等无关内容。

## 封面要求

必须基于修订正文主旨生成两张不同构图的图片：

1. **书架封面**：竖版；突出“长 PDF → 带引用的学习笔记”；顶部留标题区；无品牌 UI、无小字。
2. **阅读页封面**：16:9 横版；突出“上传、提问、点引用、核对、形成笔记”的流程；不可简单裁切竖版。

两张图片都必须保留生成模型、提示词、生成时间、原始文件 hash 和最终文件 hash。上线验收要分别回读书架卡片与阅读页，不以“文件已生成”代替“页面已展示”。
